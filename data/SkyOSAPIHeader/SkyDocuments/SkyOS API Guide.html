MODDER REFERENCE · APP AND IFRAME API

SkyOS API Header

Register internal iframe apps or native-window launchers and use the SkyOS action-bar bridge; gameplay data APIs are distributed separately.

1. Install an app without editing SkyOS

SkyOS discovers direct child app folders under Data/SKSE/Plugins/SkyOS/Apps/. Use a stable ID containing letters, numbers, underscores, or hyphens, up to 80 characters.

Data/SKSE/Plugins/SkyOS/Apps/MyJournal/
  app.ini
  index.html       (internal mode)
  style.css
  app.js
  skyos-bridge.js  (optional)
  logo.png         (optional)

Install this directory as part of your normal mod package. Open SkyApps once the mod is enabled; if the game was already running when you installed it, leave and reopen SkyApps to refresh the catalog.

2. Pick the mode in app.ini

[App]
Name=My Journal
Description=Notes from my travels
Mode=internal
Logo=logo.png

Mode=internal loads the app's index.html in the SkyOS embedded iframe. It is a sandboxed page with scripts and forms enabled. Keep CSS, JavaScript, and assets in separate files and use relative paths. HTML pages do not receive direct game, filesystem, or shell access.

Choose Mode=external for a separate native window. Add Plugin=MyPlugin.dll and optional Argument=...; SkyOS checks for the plugin already loaded by Skyrim and does not load arbitrary DLLs.

3. Embedded iframe bridge, version 1

The optional skyos-bridge.js file in SkyOSStarterKit creates window.SkyOSApp. Add it before your app script:

<script src="skyos-bridge.js"></script>
<script src="app.js"></script>

Bridge messages use { channel: "skyos-app", version: 1, type, payload }. SkyOS accepts messages only from the active app iframe. The bridge is a user interface connection; it does not add gameplay or arbitrary host permissions.

App method/eventEffect
on('host-ready', callback)Receives app ID, name, description, and bridge version.
on('visibility', callback)Receives { visible: boolean } as the user changes pages.
setTitle(text), setDescription(text)Changes the SkyOS app-page heading text.
setStatus(text)Sets the SkyOS status message.
setActions([{id,label}])Shows up to five buttons in the SkyOS action bar. IDs use letters, numbers, underscore, and hyphen; labels are text.
on('action-clicked', callback)Receives { id } when the player presses one of the registered buttons.
close()Returns the player to SkyApps.
window.SkyOSApp.on('host-ready', (host) => {
  window.SkyOSApp.setTitle('My Journal');
  window.SkyOSApp.setActions([{ id: 'refresh', label: 'Refresh' }]);
});
window.SkyOSApp.on('action-clicked', ({ id }) => {
  if (id === 'refresh') refreshMyPage();
});

Apps with a custom message implementation should compare event.source and validate channel and version. Do not trust message data from unrelated windows.

4. Native app entry point

Include SkyOSAPI.h, define SKYOS_APP_IMPLEMENTATION in the translation unit that implements the export, and return a valid visible window handle:

#define SKYOS_APP_IMPLEMENTATION
#include "SkyOSAPI.h"

HWND WINAPI SkyOS_App_Launch(const wchar_t* argument)
{
    // Create or activate a window, using argument if configured.
    // Return its valid HWND; return nullptr if launch fails.
    return nullptr;
}

The header declares the unmangled C ABI export and marks it for export when SKYOS_APP_IMPLEMENTATION is defined. The DLL must already be loaded by Skyrim. Keep the callback brief and return a valid HWND. This entry point launches a window; it is not an SKSE gameplay API.

5. Build and package

  1. Install the app registration and files into your mod's virtual Data tree.
  2. For an internal app, include its page, stylesheet, script, and any helper/assets. No app DLL is required.
  3. For a native app, package your SKSE DLL under Data/SKSE/Plugins/ and enable it in the same mod profile.
  4. For a source-tree package, configure/build as required by your project, then run cpack --config build/CPackConfig.cmake -G 7Z -C Release. The SkyOS Starter Kit is a CPack component and includes SkyOSAPI.h; the SkyRewrite, SkyCounter UI, and SkyMissions gameplay API headers are separate components.

Use SkyOSStarterKit's MODDER_GUIDE.md for detailed app, SkyViewer module, SkyDocuments, quest, and location packaging steps.

Troubleshooting

  • App is not listed: verify the direct app folder, valid ID, readable app.ini, required Name, and chosen Mode. Reopen SkyApps.
  • Internal app is disabled: confirm index.html exists beside app.ini and is non-empty.
  • Blank iframe: check local asset paths and browser syntax; keep the page within the supported 2 MiB HTML limit.
  • Actions do not appear: include the bridge helper before app.js, listen for host-ready, then call setActions().
  • Native app is disabled: confirm Plugin= names the loaded DLL basename and that the DLL exports SkyOS_App_Launch.
