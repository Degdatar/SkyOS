SkyOS Developer Tools · Field Manual 01

Modder's Starter Kit

Build an internal HTML app, a separate native app, or a SkyViewer settings module without editing SkyOS. SkyViewer is an in-game MCM-style menu built with PrismaUI, so supported mods can expose settings without Papyrus scripts or Creation Kit forms. A mod plugin still applies settings that change gameplay.

01 · SKYVIEWER MODULE

Add an MCM-style settings tab

SkyViewer builds an in-game mod settings menu with PrismaUI. Declare your settings in module.json; no Papyrus scripts or Creation Kit forms are required just to display and save those preferences.

Data/SKSE/Plugins/SkyOS/Mods/SkyViewer/<YourModule>/
  • Use a unique folder name for the module ID.
  • Add an optional Files/index.html for a custom module page.
  • Add Files/logo.png (or jpg, jpeg, webp) for its icon.
  • Settings are saved per user at %LOCALAPPDATA%/SkyOS/SkyViewer/<ModuleId>/settings.json.
  • Your plugin reads the saved values and applies gameplay changes; the UI does not create those behaviors automatically.

02 · SETTINGS SCHEMA

Manifest controls

Supported types are booleannumbertextselect. Number settings should declare min and max. SkyViewer shows both under the field and accepts the value the user types within those bounds; step is not used to round typed values. Select settings provide an options array.

Each setting needs a stable id, readable label, type, and matching default. Keep the module folder ID stable between releases because it determines the user settings path. Read the JSON from your mod plugin to apply settings in game.

03 · CUSTOM PAGE BRIDGE

Connect page controls

The page runs in a sandboxed iframe. It receives the saved values from SkyOS and can ask SkyOS to save a manifest-defined value:

Receive: { type: 'skyos:settings', module, settings }
Save: { type: 'skyos:set-setting', id, value }

See StarterTemplate/Files/index.html for the listener and a working boolean control. Requests for IDs not declared in the manifest are ignored.

04 · SKYDOCUMENTS

Ship guides and pages

Put supported files beneath a mod's SkyDocuments folder. The mod name becomes the library group, and each document is listed as a selectable tab.

Data/SKSE/Plugins/SkyOS/Mods/<YourMod>/SkyDocuments/
  • Supported: PDF, HTML/HTM, TXT, and Markdown.
  • Place logo.png at the mod package root to brand its library icon and guide heading.
  • Place an optional banner.jpg at that same package root for the wide SkyDocuments banner. PNG, JPG, JPEG, and WebP are supported; use a wide image and keep it under 1 MiB.
  • File names are case-insensitive: logo.png, logo.jpg, banner.png, or banner.jpg.
  • PDF and local HTML have a built-in reader when SkyNet is unavailable.

The banner and logo are discovered from Mods/<YourMod>/, while the guide files go inside its SkyDocuments/ folder.

05 · SKYAPPS SHORTCUTS

Launch the app from SkyApps

Internal apps appear in SkyApps by themselves. To publish a SkyViewer module shortcut, set "showInSkyApps": true in module.json. Pair it with an internal or native app by setting "nativeAppId": "YourAppId"; the ID must match the app folder under Apps/. If the external plugin is unavailable, the shortcut can open the linked SkyViewer page.

06 · INTERNAL APP · NO DLL REQUIRED

Make your own page inside SkyOS

Copy InternalAppTemplate/ to Data/SKSE/Plugins/SkyOS/Apps/<UniqueAppId>/. Edit app.ini, then freely replace the app's index.html, style.css, and app.js. Put logos, images, and other local assets beside them and use relative paths. Reopen SkyApps to refresh after installation.

Your HTML app controls its own content and design inside an isolated iframe. It does not call SkyOS internals or access gameplay directly. Add an SKSE integration for game-side features.

07 · NATIVE APP CONTRACT

Open a separate window

Copy NativeAppTemplate/ to Data/SKSE/Plugins/SkyOS/Apps/<AppId>/, set Mode=external, and export the launch entry point from your already-loaded SKSE plugin:

HWND WINAPI SkyOS_App_Launch(const wchar_t* argument)
  • Include SkyOSAPI.h in your plugin source.
  • Return your visible native window's valid HWND; return null on failure.
  • Use the plugin DLL basename in app.ini. SkyOS will not load arbitrary DLLs.
  • See NativeAppTemplate/README.md and MODDER_GUIDE.md for detailed steps and the runnable example.

08 · GAME CONTENT PACKAGING

Ship plugins, quests, and houses

Put ESP/ESL/ESM files at the normal Data/ root, with scripts, meshes, textures, and BSA files in their usual paths. Put the optional SkyOS app in its separate Data/SKSE/Plugins/SkyOS/Apps/<AppId>/ folder. Install both as a normal mod-manager package; never put an ESP inside the app folder. The app shortcut does not load plugins or implement quests/locations.

The kit's MODDER_GUIDE.md has detailed layouts and steps for plugin, quest, and house mods.
